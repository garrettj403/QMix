# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What QMix is

QMix simulates quasiparticle tunneling currents in SIS (Superconductor/Insulator/Superconductor) junctions using multi-tone spectral domain analysis (MTSDA). The math follows P. Kittara's 2002 DPhil thesis; inline comments reference specific equations from it (e.g., "Eqn. 5.25"). The source papers are in `reference/`: the PDF with the hashed name is Chapter 5 of the thesis (pp. 113-156), the others are Withington & Kollberg 1989 (single-tone spectral method, harmonic balance) and Kittara, Withington & Yassin 2007 (multitone theory applied to high-harmonic mixers). The two `stt99_*` files are from ISSTT 1999: Rice et al. (`stt99_harmonic_balance.pdf`; single-tone, multi-junction Newton harmonic balance in scattering-matrix form, with an analytic Jacobian built from the small-signal admittance matrix, eqs 23-31, an alternative to QMix's finite-difference Jacobian) and Ward et al. (`stt99_supermix.pdf`; overview of the SuperMix C++ circuit/noise library, no new tunneling math). Two papers by the QMix author describe the same 230 GHz mixer: `Simulating the Behavior of a 230 GHz SIS Mixer Using Multi-Tone Spectral Domain Analysis.pdf` (Garrett et al. 2019, IEEE TTHz; QMix vs measurements of device #6.2 with HFSS embedding impedances, the broken photon step at 236-255 GHz from a spurious 3/2 f_LO tone aggravated by an inductive embedding impedance at f_LO/2, and gain saturation vs RF power) and `GarrettJ_230ghz-sis-mixer.pdf` (Garrett et al. 2022, IEEE MWCL; the end-fire finline mixer, 33 K uncorrected at 230 GHz, noise split T_IF 7.0 K, T_RF 9.2 K, G_RF -0.8 dB, T_SIS 11 K). `GarrettJ_DPhilThesis_Chapter3.pdf` is Chapter 3 of the QMix author's DPhil thesis (a 230 GHz wide-IF-bandwidth SIS receiver): QMix's example experimental data (`notebooks/example-data/`, `tests/exp-data/`) is device #5.6 from that chapter at 230.2 GHz. Its measurement setup matters when modelling the data: hot/cold loads at 295/80 K (QMix's `PARAMS` defaults are 293/78 K), a 4-6 GHz IF band, a junction temperature of ~5.1 K (from the leakage current), and a DC I-V curve smeared by 0.02 Vgap for simulations. `GarrettJ_DPhilThesis_Chapter2.pdf` (SIS mixer theory and how the experimental noise is calculated: Y-factor with the Rayleigh-Jeans formula and physical load temperatures, Woody's shot-noise calibration, T_RF from Tong's intersecting lines) and `GarrettJ_DPhilThesis_Appendix.pdf` (Appendix A: the shot-noise calibration sets the IF reference plane at Rn, i.e., the IF mismatch is ignored; HFSS Z_IF ~7.44-17.06j ohm at 5 GHz; Appendix B: test system, loads, optics, LOs) are from the same thesis. Text extraction drops the thesis equations; render the pages to images with Ghostscript (`gs -sDEVICE=pnggray`) to read them. The `stt99_*` PDFs extract cleanly with `gs -sDEVICE=txtwrite`. The thesis chapter extracts cleanly too.

## Architecture

A simulation is a pipeline through four core modules (plus the small-signal analysis, networks and lines):

1. **`qmix/respfn.py`** — `RespFn` classes wrap a DC I-V curve and its Kramers-Kronig transform (the "response function") behind spline interpolation. For speed, `resp()` evaluates both splines as one complex piecewise polynomial (`_setup_resp_poly` / `_eval_resp_poly`); `RespFnPerfect` without smearing has no polynomial and uses its analytic functions instead. Subclasses (`RespFnPolynomial`, `RespFnExponential`, `RespFnPerfect`, `RespFnFromIVData`) differ only in the I-V model used (models in `qmix/mathfn/ivcurve_models.py`, KK transform in `qmix/mathfn/kktrans.py`). The I-V data are reflected to a grid symmetric about v = 0 and the spline knots are chosen on v >= 0 and mirrored (`_sample_curve`, which asserts a symmetric grid), so Idc is odd and Ikk even to round-off. The response function is defined for |v| <= `v_max` (35; inf for unsmeared `RespFnPerfect`); `interpolate_respfn` warns if bias + num_b·freq exceeds it. `kk_trans` is an FFT Hilbert transform of `i - v`, which must go to zero at the ends; an asymptotic offset (excess current; `RespFnFromIVData` extends data with slope 1 and keeps it) is subtracted as a smooth step with an analytic transform and added back (`_offset_step`; idea from SuperMix's log tail for Ikk). Constant offsets in Ikk cancel out of all currents.
2. **`qmix/circuit.py`** — `EmbeddingCircuit` holds the Thevenin equivalent circuit: frequencies (`freq`), voltages (`vt`), impedances (`zt`) for any number of tones (`num_f`) and their harmonics (`num_p`). `MultiJunctionCircuit(num_j, num_f, num_p)` is the multi-junction version (multi-port Thevenin: `vt[j, f, p]`, `zt[j, l, f, p]`, `vb[j, i]`, relative `area[j]` scaling each junction's current; one vgap/rn for all). The junction axis is always first and 0-indexed, so `vt[j]`, `vj[j]` have single-junction shapes; `junction(j)` gives a single-junction `EmbeddingCircuit` view (freq, vb[j]) for calling single-junction code. Functions detect it by `hasattr(cct, 'num_j')` (`qtcurrent._is_multi`).
3. **`qmix/harmonic_balance.py`** — `harmonic_balance()` solves for the junction voltage `vj` self-consistently via Newton's method. The Jacobian is analytic by default (`jacobian='analytic'`; `'numerical'` = the old forward differences, 2·num_n `qtcurrent` calls, step `DV`). `qtcurrent.qtcurrent_derivatives` gives dI/d(Re, Im) vj[f, p] as `d[o, f, p, c, i]`: perturbing harmonic q shifts the tone's phase factor coefficients, dC_k/dRe V_q = (C_{k-q} - C_{k+q}) / 2qw, dC_k/dIm V_q = -j (C_{k-q} + C_{k+q}) / 2qw (coefficients computed with num_b + num_p so the shifts exist), so derivatives are the MTSDA sums with one tone's pair products replaced by `dC C* + C dC*` (`_PairCache` keys (f, a) and (f, a, (q, c))); no response-function derivatives. Direct method: `_deriv_coeff_batched` (one pass per batch; the innermost-tone sum is shared by all outer-tone derivatives via prefix/suffix products, only innermost-tone derivatives need their own inner sums); Fourier: generic `_sum_terms_fourier` on keyed terms. Matches central differences ~1e-9 for num_p = 1; with harmonics it differs from FD of the truncated convolution at the truncation level (needs adequate num_b). HB 1.2-1.5x faster (1 junction, 1-4 tones), ~1.9x for 2 junctions; the analytic Jacobian converges the hard strong-pumping test case even without the line search (`test_line_search_hard_case` pins `jacobian='numerical'` for the no-line-search assertion). The Jacobian is reused across iterations while each iteration still cuts the max relative error by `JACOBIAN_REUSE_RATIO` (`reuse_jacobian=False` gives plain Newton). Each step goes through a per-bias-point backtracking line search (`_line_search`, sufficient decrease of |e|^2); the trial evaluation doubles as the next iteration's error, so full steps are free. A point with no acceptable step under a stale Jacobian keeps its voltage and forces a new Jacobian; under a fresh one, it is restarted from the nearest converged bias point (`MAX_RESTARTS`). `line_search=False` reproduces the old behavior exactly. Converged bias points keep being updated while others are still converging, so most points end up far more accurate than `stop_rerror` (median ~1e-12 at the default 1e-3); freezing them and iterating only the unconverged points was tried and rejected (only 5-30% faster, but typical accuracy dropped to ~1e-5). `warm_start=True` seeds the strongest tone from a single-tone solve (opt-in: usually 2-3x fewer iterations, occasionally slower). The main loop works on flat `vj_2d[k, i]` through two closures, `error_vector` and `inv_jacobian`: for one junction they wrap the original `_error_vector`/`_inv_jacobian` (numerics unchanged), for a `MultiJunctionCircuit` they come from `_MultiJunctionSystem` (k = j * num_n + n; each junction's current depends only on its own voltage, so J = -1 - Z dI with dI per junction: `inv_jacobian_analytic` from `qtcurrent_derivatives`, or `inv_jacobian` perturbing signal q of all junctions at once, 2·num_n current calls per junction). `qtcurrent`, `interpolate_respfn` (one resp matrix per junction, shared between junctions with the same resp object and vb), `suggest_num_b` and `check_hb_error` also accept the multi-junction circuit; `resp` may be a list (`qtcurrent.junction_resp`).
4. **`qmix/qtcurrent.py`** — `qtcurrent()` computes the tunneling current for given `vj` at requested output frequencies. This is the compute core: for 3+ tones nearly all simulation time is in `_current_coeff_batched`, whose cost (and the size of `resp_matrix`) scales with the product of (2·num_b + 1) over tones. `suggest_num_b(vj, cct)` picks per-tone limits from a solved `vj` (not `cct.vt`: IF tones can be driven by mixing even when `vt` is 0). When that product gets large (`method='auto'` switches above `MAX_RESP_MATRIX_BYTES`, or pass `method='fourier'`), the Fourier-shift path (`FourierResp` / `_current_fourier`) sums each tone separately at a cost that is additive in the tones; its accuracy is set by the spline smoothness of the response function (~1e-7 with cubic splines, ~1e-9 with `spline_order=5`), so it is not used for the 14-decimal benchmark checks. The theory is written up in `docs/source/fourier-shift-method.rst`. `interpolate_respfn` returns a `FourierResp` instead of a matrix in that case; `qtcurrent` accepts either as `resp_matrix`.

5. **`qmix/small_signal.py`** — Tucker small-signal analysis on top of a single-tone LO state: `admittance_matrix` (conversion admittance matrix between sidebands m·f_lo + f_if, m = -num_sb..num_sb), then `sideband_impedances`/`sideband_voltages`/`solve_sidebands`/`conversion_gain`. Sideband arrays are in natural order (index m + num_sb); for m < 0 the frequency is negative, so phasors, sources and impedances there are complex conjugates of the physical LSB values (the helpers convert; `lsb()` converts back). The formula is SuperMix's `small_signal` (fIF != 0 branch) collapsed to one expression for signed m, n; it needs f_if > 0 (the f_if = 0 limit, e.g. for an analytic harmonic-balance Jacobian, would need derivatives of the response function, as in SuperMix). Checked against SuperMix Y to ~5e-14 and against QMix multi-tone gain to ~1e-6. Noise: `noise_matrix` (H, one-sided spectral density of RMS noise currents, normalized to e·Igap; temperature in K and `vgap` needed), `embedding_noise` (Callen-Welton Thevenin noise of each sideband impedance), `output_noise` (A (H + Y S Y^†) A^†, A = (1 + YZ)^-1; load noise excluded) and `noise_temperature` (SSB; excludes input and output sidebands; junction-only noise can be below the quantum limit). Checked against SuperMix's mixer analysis (`profile/supermix/compare_noise.py`, driver mode `mixernoise`) to ~1e-15, but only with SuperMix's CODATA-1986 constants swapped in (tests monkeypatch `qmix.small_signal.sc`); with SciPy's constants noise temperatures differ by 6.1e-6. Several junctions: `admittance_matrix`/`noise_matrix` accept a `MultiJunctionCircuit` (one matrix per junction, area-scaled, junction axis first). The embedding network at each sideband is a (J+1)-port impedance matrix: junction ports + one external port (RF source at RF sidebands, IF load at the IF), terminated by `z_ext` (`sideband_networks`, conjugated for m < 0; `qmix.network.impedance_matrix` builds them). `_network_response` reduces it to the junction-port Thevenin (Z_T = Z_JJ - Z_Jx Z_xJ / D, D = Z_xx + z_ext) and solves `(1 + Y Z_T) I = dI + Y n` over (j, m) (k = j * dim + m + num_sb); load current = Z_xJ I / D + direct terms. `network_gain`, `network_output_noise` (junction H, terminations `temp_ext`, network noise `temp` via Twiss `2 k T_cw (Z + Z^H)`), `network_noise_temperature`; y/h without a junction axis are accepted (one junction behind a lossy network). Tests: equal to the single-junction functions behind a lossless T network, parallel pair = area 2, thermal equilibrium k T_cw (1 - |Gamma|^2), multi-junction multi-tone HB (~1e-6). Multi-tone checks at a low IF need a very weak RF signal: the IF photon voltage is tiny, so the IF drive level isn't small otherwise (1 pW at 5 GHz IF gave 0.5% errors with num_b 3 for the IF).

6. **`qmix/network.py`** — S-parameter networks (`Network`: interpolate, renormalize with power waves, connect, terminate, `impedance` at a port; `read_touchstone`, incl. HFSS per-frequency `! Port Impedance` comments when the option line has no `R`). Ports are 1-indexed, frequencies in Hz, impedances in ohms (not normalized). `embedding_impedance(network, port, cap, terminations)` gives Z(f) with the junction capacitance in parallel (spline of the reflection coefficient); `PumpedData.mixer_noise(z_emb=...)` uses it for the sideband impedances. `thevenin(network, freq, port, source_port, power, phase, cap, terminations)` adds the Thevenin voltage for a source of given available power at another port (power waves, peak amplitudes: `V_T = 2 sqrt(Re Z_ref,j) S_js a_s / (1 - S_jj)`, `|a_s|^2 / 2 = power`; source internal impedance = its reference; only where the source port's reference has Re > 0, i.e., waveguide above cutoff), and `set_thevenin(cct, network, f, p, ...)` writes the normalized values into an `EmbeddingCircuit` (frequency `p * cct.freq[f] * cct.fgap`), so S-parameter circuits drive the harmonic balance; Example #4 fits the LO power in the waveguide (47 nW at 220.1 GHz). Load reflection at a network port is `(Z - Z_ref)/(Z + Z_ref^*)`, so "matched" = terminated by `Z_ref` (fixed Nov 2026; was the conjugate, wrong for complex references; tests check against the Z-matrix). Ports whose reference is not a valid power-wave reference (imaginary: waveguide below cutoff) are connected directly and left unrenormalized. With a list of junction ports, `thevenin`/`set_thevenin` give the multi-port Thevenin (`_thevenin_ports`: Z from the junction ports' S-matrix, `F^-1 (1-S)^-1 (S G + G^*) F`; open-circuit V_T; per-junction caps via `(1 + Z Y_c)^-1`) for a `MultiJunctionCircuit`; checked against the Z-matrix circuit solution, and an ideal tee with two identical junctions equals one junction with Rn/2. Circuit elements: `transmission_line(freq, zc, gamma, length, z0=None)` (ABCD -> S with the real reference `zc.real`, so a lossless line is matched; waves `exp(-gamma z)`), `tee(freq, z0, num_ports)`, and `microstrip(freq, width, height, eps_r, thickness, strip, ground, temp, tan_d, eps_up, tan_up)` -> `(zc, gamma)` (scalars for scalar freq) / `microstrip_line(freq, length, ...)`: SuperMix's model transcribed (Hammerstad-Jensen static eps_eff with thickness correction, Kirschning-Jansen dispersion with f*h in GHz*mm, Yassin-Withington g1/g_strip/g_ground; `Z' = j k Z0 + g_s Zs_strip + g_g Zs_ground`, `Y' = (k/Z0)(2 delta + j(1 - delta^2))` with SuperMix's half loss tangent); needs thickness > 0 (YW diverges at t = 0); films are duck-typed (`zs(freq, temp)`, `thickness`; `None` = perfect conductor). Physical constants via `qmix.network.sc` (SciPy) so tests can monkeypatch.

7. **`qmix/superconductor.py`** — films for those lines (SI units, exp(+j w t), sigma = sigma1 - j sigma2): `energy_gap(temp, tc)` (Delta(T)/Delta(0) from the weak-coupling BCS gap equation via brentq, xi = Delta sinh u; 1 for t <= 0.02; matches Muhlschlegel's table to its 4 digits), `mattis_bardeen(freq, temp, vgap, tc)` (sigma/sigma_n, Kautz form in reduced units Omega = hf/Delta(T), tau = kT/Delta(T); quad with `weight='alg'` for the endpoint inverse-sqrt singularities, x = 1 + s^2 for the thermal term; ~0.2 ms/point; matches the T = 0 elliptic-integral closed form to ~1e-12 incl. the gap edge; vgap gives Delta(0) independently of tc), `film_impedance(freq, layers, z_back=None)` (SuperMix's local_film/layerList transmission-line formula incl. displacement current, layers listed from the current-carrying side, default backing Z_vac read at call time), `NormalFilm`, `SuperconductingFilm` (dict cache keyed (freq, temp), cleared when vgap/tc change; `penetration_depth`, `fgap` = T = 0), `Multilayer`. Cross-checked by `profile/supermix/smx_lines.cc` + `compare_lines.py` (`--save` -> `tests/supermix-data/supermix_lines.npz`, `test_microstrip` in `test_supermix_reference.py`, monkeypatching `sc` in both modules with SuperMix's CODATA-1986 constants and mu_0 = 4 pi 1e-7): normal metals ~1e-15; superconductors ~2e-8 (SuperMix's integrator; 1.7e-6 at the gap edge) at 0.3 K, ~1e-4 at 4.2 K (SuperMix's Muhlschlegel table vs BCS).

`qmix/exp/` analyzes experimental data (I-V and IF spectra), fitting it into the same pipeline via `RespFnFromIVData`; `exp_data.py` is its main entry point. IF powers are calibrated to K with Woody's shot-noise method (slope e/2k = 5.8 K/mV above the gap; IF mismatch ignored), so the measured `gain` is total DSB gain (optics x mixer x IF coupling) and `tn` the DSB receiver noise. `PumpedData.mixer_noise` compares these with `qmix.small_signal`: it simulates the mixer with the recovered `vt`/`zt` and fits only an RF/optics stage (`g_rf`, `t_rf`) via gain = g_rf g_mix and T_rx = t_rf + (t_mix + t_if/g_mix)/g_rf. f_if, z_if, temp are user inputs (not in the data). t_mix doesn't depend on z_if, but g_mix (so the g_rf/g_mix split) does: the measured gain is referred to an rn reference plane (Woody calibration ignores the IF mismatch; thesis Appendix A), so the gain into the real Z_IF corresponds to g_mix / (1 - |G|^2), G = (z_if - rn)/(z_if + rn) (not applied in the code). With the thesis' HFSS Z_IF (7.44-17.06j ohm at 5 GHz, factor 0.56) the example data give g_rf 0.77 / t_rf 23 K (letter: G_RF 0.83), vs 0.52 / 21 K at 50 ohm without the factor; but the gain shape across the step fits worse (rms 0.44 vs 0.25). LO-harmonic sidebands change t_mix by only ~0.2 K; the ~8 K gap to the thesis noise split (intersecting-lines T_RF <= 12.6 K) is unresolved, and it is not a zero-point convention issue (the measured Tn uses physical ~ Callen-Welton load temperatures). The simulated photon step is ~0.05 mV wider than measured (not explained by those inputs).

Worked end-to-end examples (single-tone and multi-tone simulations, experimental-data analysis, HFSS embedding impedance and the broken photon step, power saturation, and Example #6 `multi-junction-mixer.ipynb`: a twin-junction mixer built from ideal lines with `qmix.network`, multi-junction HB, small-signal gain/noise, a multi-tone check, a lossy tuning circuit, and the same circuit from Nb/SiO2/Nb microstrip (designing without kinetic inductance moves the resonance from 230 to ~180 GHz)) are in `notebooks/`; they mirror the examples on the documentation website.

### Conventions that span the codebase

- **Everything is normalized**: voltages to the gap voltage `Vgap`, currents to `Igap = Vgap/Rn`, frequencies to the gap frequency. Un-normalized values appear only at the `exp/` and `RespFn` construction boundaries.
- **Array index order** (per CODE_GUIDELINES.md): frequency/tone `f`, harmonic `p`, summation index `k`, bias-voltage point `i` — e.g. `vt[f, p]`, `ckh[f, p, k, i]`. The `f` and `p` axes are **1-indexed**; row/column 0 is unused padding.
- **Wraparound indexing for summation indices**: arrays over the Bessel summation index `k` (response-function matrices, phase-factor coefficients) store k = 0..num_b in positions 0..num_b and k = -num_b..-1 at the end, so code indexes them directly with negative `k`. Both NumPy and Numba handle this via negative-index wraparound. Keep this convention when touching `qtcurrent.py`.
- **Frequency matching by rounding**: output frequencies are matched to harmonic combinations `a·f1 + b·f2 + ...` after rounding to `ROUND_FREQ` (4) decimal places (defined in both `qtcurrent.py` and `harmonic_balance.py`). Tones or IFs closer than ~1e-4 (normalized) will alias.
- **One batched kernel for any number of tones**: `_current_coeffs` collects every term of every output frequency (the +a and -a parts of each index combination) and `_current_coeff_batched` evaluates up to `MAX_BATCH_TERMS` (32) of them in one pass over `resp_matrix` reshaped to 2-D (all tone indices flattened in C order, bias points last); the kernel is memory-bound, so sharing each read of the matrix is the main win. The outer tones' indices are decoded from the row number (mixed radix), each term's running pair products are updated odometer-style from the first index that changed since the previous row, and per row and term the sum over the last tone is formed first and multiplied by the running product once (one complex multiply per inner step). Per-term, per-tone validity masks skip empty terms (pair products are zero there anyway). `_current_coeff` is a single-combination wrapper (used in tests). Output frequencies are matched to index tuples by `_matching_tuples` (all |a_f| <= num_p) plus `_add_mixing_products`: with commensurate tones, combinations with larger indices land on output frequencies too (thesis Eqn. 5.36), some first order in the signals (2 * LO - LSB = USB). Candidates up to |a_f| <= 2 * num_b_f are enumerated by meet in the middle (`_candidate_tuples`, cached) and kept if the bound prod_f sum_k |C_k||C_{k+a_f}| exceeds `MIXING_TOL` (1e-6) times the largest bound of that output's |a_f| <= num_p tuples (relative, so the kept set doesn't depend on signal strength; an absolute tolerance broke small-signal extrapolation; errors ~1e-7 relative; `mixing_tol=np.inf` reproduces the old |a_f| <= num_p behavior exactly). Dropping them used to cause errors of 1e-2 in currents and up to ~50% in mixer responses with both sidebands as tones (checked against SuperMix small-signal theory, `profile/supermix/compare_multitone.py`). With the batched kernel (Nov 2026), commensurate 3-4 tone simulations are ~2x faster than with one pass per term, but still slower than before the extra terms were included (4-tone HB benchmark: 1.1 s before the fix, 4.0 s with per-term passes, 2.6 s batched). Because the summation order depends on the number of tones, results for different tone counts agree only to ~1e-13: tests compare them with `assert_allclose`, not `assert_equal`.
- **Numba kernels**: the hot kernels use `@nb.njit` with explicit signatures (eager compilation) and `cache=True`. They carry `# pragma: no cover` because coverage can't trace compiled code — the surrounding pure-Python wrappers are what tests exercise directly. Kernels avoid temporary array allocations (explicit loops over bias points, pair products pre-computed with `_pair_products`, invariant products hoisted per loop level); preserve that style when editing.
- **Parallel kernels**: `_current_coeff_batched` and `_eval_resp_poly` use `parallel=True` with `prange`. The current kernel parallelizes over 4 chunks of rows per thread (64 per thread was ~1.5x slower once batched), each accumulating into its own slot per term (no shared writes; the slots' memory, terms x chunks x npts, is capped by `BATCH_ACC_BYTES`); keep the bias-point loop innermost so memory access stays contiguous (parallelizing over bias points instead was ~3x slower). With `cache=True`, never compile the same Python function twice with different flags (e.g., serial and parallel): the cache keys on function and signature, so one silently loads the other. With Anaconda's Numba (OpenMP threading layer), a harmless `OMP: Info #276 ... omp_set_nested` notice prints once per process; `qmix/_omp.py` (imported first in `qmix/__init__.py`) silences it with `KMP_WARNINGS=0` (setdefault, so the user can override; no effect if Numba ran a parallel kernel before `qmix` was imported).

## Roadmap (open items, Nov 2026)

The SuperMix capability gap is mostly closed (noise, multiple junctions, S-parameter circuits, analytic HB Jacobian, superconducting microstrip are done). Still open, roughly in order of value:

- **Series arrays**: every junction in a `MultiJunctionCircuit` is voltage biased at its own `vb[j]` (no DC network), so series arrays (one bias across N junctions, DC current shared) can't be simulated yet. Needs a DC embedding (the DC voltages become unknowns in the harmonic balance, constrained by the shared current), and a way to pass one bias for several junctions.
- **Small-signal analysis from a multi-tone LO state**: `qmix.small_signal` assumes a single-tone LO (`vj` with one tone and its harmonics). With two LOs or a sub-harmonic/spurious tone (e.g., the 3/2 f_LO tone in Example #4, or the two-LO data in `profile/thesis/two_lo.py`), gain and noise currently need full multi-tone simulations. The admittance and noise matrices would generalize over the mixing products of all LO tones.
- **Multi-tone noise**: shot noise (the H matrix) is only available in the small-signal analysis, i.e., for a single-tone LO; the same generalization as above.
- **Lossy superconducting CPW** (deliberately left out of the microstrip work: SuperMix's CPW is lossless, so there is no reference to check against).
- **Different junctions in one circuit**: `MultiJunctionCircuit` has one `vgap`/`rn` for all junctions (only `area` differs; `resp` can already be a list).
- Small items: `profile/benchmark/benchmark-harmonic-balance.py` times `two_tone` in the 3-tone section (`timeit.Timer(two_tone)` should be `three_tone`; leave fixing it and re-recording timings to the user). The small-signal analysis needs f_if > 0.

## Code style

- Google-style docstrings for public modules/functions/classes; private (`_`-prefixed) functions may use inline comments instead.
- Dependencies restricted to the standard library, NumPy, SciPy, Numba, and Matplotlib.
- ASCII only (no unicode in source); American spelling.
- flake8 line limit is 120; ignores include alignment-related codes (E221, E222, E251), so vertically aligned assignments are fine and already common in the code.
